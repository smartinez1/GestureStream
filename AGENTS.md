# AGENTS.md

## Project Overview

GestureStream is a real-time gesture-controlled 3D interaction app with two frontends:
- **Python** (single package): MediaPipe hand tracking -> 3D cube + image overlays. No tests, no linter, no build step, no CI (`.github/workflows/` is empty).
- **Web app** (`web/`): Vercel-deployable Canvas2D port of the same effects + gestures (branch `web-app`; `vercel.json` at repo root). All gesture logic is ported 1:1 from the Python state classes.

## Architecture

- `core/gesture_stream.py` is the **core**: defines `GestureStreamController` (all detection, rendering, overlay logic) and runs the camera loop.
- `core/gesture_stream_advanced.py` (`AdvancedGestureStream`) and `core/gesture_stream_demo.py` (`GestureStreamDemo`) both `import` the core and **subclass** `GestureStreamController`. Changes to core methods (e.g. `detect_pointing_gesture`, `draw_3d_cube`) affect all three scripts. Both scripts use `super().__init__()`, so core `__init__` changes are inherited.
- `core/gesture_stream_diffusion.py` is the **diffusion module**: self-contained (`VoxelDiffusion`, no core import), imported by the core — so the core can never be imported by it (circularity). Also runnable standalone as a synthetic demo.
- **`sys.path` shim pattern:** `core/gesture_stream.py`, `core/gesture_stream_advanced.py` and `core/gesture_stream_demo.py` each start with `sys.path.insert(0, os.path.dirname(__file__))` so their cross-module imports (`from gesture_stream import GestureStreamController`, `from gesture_stream_diffusion import VoxelDiffusion`) still resolve when the script is run directly (e.g. `python3 core/gesture_stream_demo.py`) from any working directory. The diffusion module and the `effects/` scripts have no project imports and need no shim.
- `effects/` holds the three **standalone effect scripts**: `effects/gesture_stream_fire.py` (`FireEffect`, `FireGestureController`, `FireGestureState`), `effects/gesture_stream_tree.py` (`VoxelTree`, `TreeGestureController`, `TreeGestureState`), `effects/gesture_stream_effects.py` (`Kaleidoscope`, `PersonSegmenter`, `ColorDiffusion`, `GestureEffectsController`, `KaleidoscopeGestureState`, `WaveGestureState`, `PersonTrackerState`). All are self-contained (no core import, MediaPipe Task API used directly) and each has a camera path plus a `--demo` synthetic path. The controllers own the MediaPipe setup and delegate all gesture logic to their state classes (see "Gesture State Classes").
- `gesture_stream_showcase.py` (repo root) is the **thin orchestrator**: `ShowcaseController` creates one shared `HandLandmarker` and one shared `PersonSegmenter`, instantiates all four rendering objects (`FireEffect`, `VoxelTree`, `Kaleidoscope`, `ColorDiffusion`), and delegates all gesture logic to the five state classes (`FireGestureState`, `TreeGestureState`, `KaleidoscopeGestureState`, `WaveGestureState`, `PersonTrackerState`) — all imported from the `effects/` scripts. **No gesture logic is duplicated.** Every frame `process_frame` feeds the same hand data to the state objects, then renders in fixed order: kaleidoscope remap -> color trail paint -> tree -> fire -> HUD (`h` toggles the HUD, `q` quits). Fire is L-gated (an L sign lights it at that palm; the other hand's vertical position = heat, no toggle); the tree grows from a palms-up spread -> together squeeze; the kaleidoscope is toggled by a 0.6 s prayer-pose hold; the trail by 3 both-hand swings. `update_person` (via `PersonTrackerState`) runs on the raw (unremapped) frame before `process_frame` so the kaleidoscope box and trail mask never come from an already-processed frame. `--demo` drives all four effects synthetically (stylized person on the left, palms on the right).
- **Gesture State Classes** — pure gesture logic (no MediaPipe, no camera), each exposing an `update(...)` and holding its own state, so any script can share them:
  - `FireGestureState` (`effects/gesture_stream_fire.py`) — `update(hands, frame_size) -> (trigger_center | None, heat, burning)`. Trigger = an L sign (index + thumb extended, other fingers curled; the L hand anchors the flame). Heat = `1 - palm_center_y` of the non-anchor hand (top of frame = max fire, bottom = no fire; no second hand = heat decays to 0). Smoothed at `HEAT_SMOOTHING = 0.12`/frame. The binary pop is removed by a smoothed `flame` level (`BURN_SMOOTHING = 0.12`/frame, `burning = flame > 0.02`) plus an L-dropout grace (`L_GRACE_FRAMES = 6` — brief sign/tracking flicker keeps the flame + anchor alive; callers scale spawn heat by `heat * flame`).
  - `TreeGestureState` (`effects/gesture_stream_tree.py`) — `update(hands, handedness, frame_size, now, tree)`. Drives idle -> spread -> together; the spread->together squeeze and the hold count only while both palms face up — `_palm_normal` is the 3D cross product of wrist->middle-MCP and index-MCP->pinky-MCP, its y-component must point up (sign flips by MediaPipe `handedness`: "Left" -> `n_y > +PALM_UP_NORMAL_Y` (0.45), "Right" -> `< -0.45`; calibrated on the real camera's mirrored pipeline), smoothed over `PALM_UP_CONSECUTIVE = 3` frames so z-noise can't flicker the gate (a vertical prayer pose arms but never spawns the tree). Spawns/fades the `VoxelTree` directly. Exposes `anchor`, `state`, `palms_up`.
  - `KaleidoscopeGestureState` (`effects/gesture_stream_effects.py`) — `update(hands, now) -> fired(bool)`. Prayer-pose hold (`HOLD_TIME = 0.6` s) toggles `enabled` on the rising edge. Exposes `enabled`, `praying`.
  - `WaveGestureState` (`effects/gesture_stream_effects.py`) — `update(hands, now) -> fired(bool)`. Three both-hand swings toggle `wave_enabled` (hysteresis per-axis turn detection, `WAVE_GRACE` hand-drop grace). Exposes `wave_enabled`, `waving`.
  - `PersonTrackerState(segmenter)` (`effects/gesture_stream_effects.py`) — `update(frame)`. Throttled segmentation (`SEGMENT_EVERY = 3`) + median filter (`BOX_SMOOTH_WINDOW = 5`) + low-pass ease (`ANCHOR_SMOOTHING = 0.15`). Exposes `person_rect`, `center`.
  - The effect scripts' controllers (and the showcase) construct these directly; tuning a gesture means editing the state class once — it propagates everywhere.
- **Two-phase animation** (requires a pointing hand present): on the other hand's closed -> open transition, `process_frame` calls `VoxelDiffusion.trigger()` to **explode** the currently shown image into expanding voxels; on open -> closed it advances `image_index` and calls `VoxelDiffusion.reconstruct()` — voxels converge back onto the cube while their colors morph from the old image's palette to the next image's (`color_from` -> `color_to` lerp). **The explosion does not destroy the image:** it expands until `EXPLODE_CAP` (0.6) progress, then holds there indefinitely (voxel cloud, `is_active()` stays True for explode mode) until the hand closes — the next image appears only on close. **Reconstruction starts from the current animation state, not a default size:** `reconstruct()` records `start_state` (the explosion's progress at the close moment) and blends radius/size/alpha continuously from that state to the cube (verified: closing mid-explosion at 0.5 starts at the half-expanded radius; closing from the held state starts at the cap).
- **Animation duration follows the hand's transition speed** (default 5.0 s, measured transition doubled and clamped to 0.8–6.0 s): `_hand_openness()` (mean tip-to-PIP distance / palm size, scale-invariant) is sampled per frame into per-state deques (`openness_open` / `openness_closed`, maxlen 90) for the non-pointing hand; `_transition_duration(history, current_openness, opening)` measures time since openness left the previous state's resting level (median of that state's deque) by 15% of the span, then doubles it — fast flips get ~0.8 s, slow opens/closes get proportionally longer (verified: 3 s physical ramp -> ~2 s, 0.2 s ramp -> 0.8 s).
- `run()` / `run_advanced()` draw `draw_voxels` during either mode, otherwise the current image as-is at the cube position (`draw_image_on_cube`, alpha-composited, BGRA). **No image texture drawn during the burst.** **The projected image follows the cube's orientation:** `draw_image_on_cube(..., rotation=)` warps the image onto the plane perpendicular to the orientation (same `rz@ry@rx` convention as `draw_3d_cube`, orthographic projection, foreshortens with tilt); the rotation used is NOT the raw `cube_rotation` but `projection_rotation`, which eases toward the hand's orientation at `ORIENTATION_SMOOTHING = 0.03` per frame via `_ease_projection_rotation` (shortest-arc per axis so angles don't spin at the -pi/pi boundary) — the raw orientation is jittery, so the image drifts slowly instead of snapping. Pitch/yaw are clamped to `MAX_PROJECTION_TILT` (0.6 rad) so the plane never tilts edge-on or back-facing (always visible from the user's perspective); roll is unclamped. Images come from `images/` (configurable via `image_folder` param; loaded at 400x400 and drawn on the cube at `size * 4` px — 160 px at the default size 40; alpha is composited onto white, and palette extraction in `VoxelDiffusion._extract_palette` excludes near-white/near-black pixels and samples weighted by saturation so flat backgrounds don't swallow the image's actual colors). The old overlay-on-open-hand behavior in the run loops was replaced by this cube projection, but `overlay_image_on_hand` still exists (demo history).
- Each script has a `main()` guarded by `if __name__ == "__main__"`. All are run directly: `python3 core/gesture_stream.py` (camera), `python3 core/gesture_stream_advanced.py` (camera + recording/effects), `python3 core/gesture_stream_demo.py` (no camera, synthetic data), `python3 core/gesture_stream_diffusion.py` (no camera, standalone burst demo), `python3 effects/gesture_stream_fire.py` / `python3 effects/gesture_stream_tree.py` / `python3 effects/gesture_stream_effects.py` (camera, `--demo` for synthetic), `python3 gesture_stream_showcase.py` (camera, `--demo` for synthetic).

## Web App (`web/`)

- **Vite + Canvas2D port** of the Python effects/gestures, on branch `web-app` (root `vercel.json` builds `web/` and serves `web/dist`). Runs fully in-browser via MediaPipe Tasks API (`.wasm` bundle served from the `@mediapipe/tasks-vision` npm package) — no Python, no backend. `npm run dev` (Vite dev server, HMR), `npm run build` (output `web/dist`), `npm run preview`. `?demo=1` runs a synthetic no-camera demo; without it the app requests camera + MediaPipe models (browser needs camera permission).
- **Modules mirror the Python classes 1:1**: `web/src/gestures/fireGesture.js` (`FireGestureState`, L-sign trigger + heat + `flame` smoothing, `L_GRACE_FRAMES`), `treeGesture.js` (`TreeGestureState`, palms-up cross-product gate with handedness-sign flip), `kaleidoGesture.js` (`KaleidoscopeGestureState`, 0.6 s prayer-hold toggle), `waveGesture.js` (`WaveGestureState`, 3-swing toggle, plus `PersonSegmenter`/`PersonTrackerState`), and `web/src/effects/` (`fire.js` `FireEffect`, `tree.js` `VoxelTree`, `kaleidoscope.js`, `colorDiffusion.js`). `web/src/main.js` wires it all together (render loop, demo state machine, status bar), `web/src/mediapipe.js` wraps the Tasks API init. **Tuning a gesture means editing the shared state class once — it propagates to every script and the web app.**
- **Gesture logic lives in the state classes** (`web/src/gestures/*.js`); the render path in `web/src/main.js` calls `gestureState.update(hands, ...)` each frame and draws effects in the same order as `gesture_stream_showcase.py`: kaleidoscope remap -> color trail -> tree -> fire -> HUD. Status bar in `index.html` (`#status` spans `#fps`, `#eff-fire`, `#eff-tree`, `#eff-kaleido`, `#eff-trail`) toggles `.on` classes; `h` toggles the HUD panel (canvas-drawn, not DOM).
- **`willReadFrequently` perf rule:** any canvas context that gets `getImageData`-read every frame (fire body, wave trail mask, kaleido remap, demo person mask) must be created with `getContext("2d", { willReadFrequently: true })` — without it Chrome degrades to software raster and FPS collapses. Keep this in mind when adding new effects.
- **Demo phases** (`main.js` `createDemoState()`): 4 phases × 9 s = 36 s cycle. fire (0-9 s: L sign + modulator hand bobbing for heat) -> tree (9-18 s: palms-up squeeze) -> kaleido (18-27 s: prayer-hold toggle) -> wave (27-36 s: swings toggle trail). The demo `synHand` helper builds 21-landmark hands; note `dy = wy - 0.8` shifts the whole hand — tip Y constants must NOT add `dy` themselves (the final `.map()` applies it once), or fingers double-shift and break the L-sign curl check at `wy != 0.8`. Handedness labels must match the template: `side=-1` is "Right" geometry, `side=+1` is "Left" (the tree palm-up gate flips on this — inverted labels silently kill the tree phase).

## Environment & Setup Gotchas

- Deps are **already installed** on this machine (Python 3.12.7, mediapipe 1.0.0, opencv 5.0.0, numpy 2.3.3, Pillow 11.3.0). `requirements.txt` pins older versions (`numpy==1.24.3` supports Python <= 3.11, `opencv-python==4.8.1.78`); a fresh `pip install -r requirements.txt` on Python 3.12+ may fail or downgrade a working env. Only reinstall if something is actually broken.
- **First run downloads the MediaPipe model** (`hand_landmarker.task`, ~7 MB) from Google storage to `~/.mediapipe/models/` in the **home directory, not the repo** (the `.gitignore` `.mediapipe/` entry is misleading). `core/gesture_stream_demo.py` also triggers this download because it inherits the core constructor. Runs are offline-capable only after the download.
- Uses the MediaPipe Task API (`mp.tasks.vision.HandLandmarker`) in `VIDEO` running mode; `detect_for_video()` requires monotonically increasing timestamps per call.
- Camera apps open a GUI window and need macOS camera permission for the terminal/Python process; they fail (or just show nothing) in headless environments — use the demo there.

## Verification

No test framework exists. Verify changes with `python3 -m py_compile <file>.py` and, when camera is available, run the affected script. The demo is the safe smoke test (no camera) but it does exercise the model download + MediaPipe init. For the web app: `npm run build` in `web/`; a `node` smoke test over the gesture modules can be run directly (ESM imports of `web/src/**/*.js` work standalone).

For logic verification without a camera, a synthetic harness works: stub `controller.hand_landmarker.detect_for_video` to return a fake result with two hand-landmark lists, stub `detect_pointing_gesture`/`detect_open_hand_gesture` (identity-check on the landmark list's first element — `process_frame` copies the list, so identity on the list fails), patch `gesture_stream.time.time` with a fake clock (timestamps otherwise collapse to ~0 and durations clamp to the 0.8 s minimum), and mutate the landmark `.x/.y` attributes per frame to drive openness ramps. Note: landmark y is normalized with y increasing downward, and openness ~= tip offset / palm distance (~12.5x the tip offset for a palm of 0.08).

## Code Conventions & Tuning Points

- Gesture thresholds live in `detect_pointing_gesture()` (index extended, others curled; default `0.05` offset) and `detect_open_hand_gesture()` (>= 4 of 5 fingers extended; default `0.03` offset) in `core/gesture_stream.py`. Hand landmarks are normalized (x, y) with **y increasing downward**.
- Frames are mirrored (`cv2.flip`) before processing; MediaPipe requires RGB input (`cv2.cvtColor` BGR->RGB). Overlay uses 50/50 `addWeighted` blend. MediaPipe confidence thresholds default to `0.5` (constructor args in `core/gesture_stream.py`). Cube rotation is smoothed over the last 5 frames (`deque(maxlen=5)`). Note: `toggle_debounce` and `last_toggle_time` (in `core/gesture_stream_advanced.py`) are dead variables — the `r`/`m` toggles have no debounce.
- Keyboard: `q` quits; `r`/`m`/`i` toggles in the advanced version only (`i` hides the gesture-status panel, `r`/`m` toggle recording/metrics); `h` toggles `show_annotations` (hides cubes/arrow/hand keypoints, keeps the projected image) — the flag lives in the core (`core/gesture_stream.py`), checked by `draw_hand_landmarks` and the run loops. In `gesture_stream_showcase.py`, `h` toggles the HUD panel instead. Recordings go to `gesture_recordings_*/` (gitignored).
- Gitignore also covers `*.mp4`, `*.avi`, `*.task`, `temp_frames/` — keep those out of commits.
